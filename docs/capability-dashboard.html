How the system works

Capabilities below distinguish implemented mechanisms, tested behavior, and the target for each area.

Current supervised workflow

  1. Enter and route

    Claude Code /aegis, standalone read-only discovery, or the local discovery UI.

  2. Investigate and implement

    Specialists read source and relevant references. Claude Code can implement within human-approved scope.

  3. Review evidence

    Inline checks, a read-only verifier where allowed, or a separate reviewer using SDD records.

  4. Gate handoff

    SDD checks approval, file scope, working state, evidence, and freshness. Humans control release.

Target governed workflow

  1. Approve the spec

    Set behavior, risk, edit boundaries, acceptance checks, and decisions that require a human.

  2. Assemble relevant context

    Use current code intelligence, approved memory, and proportional model routing to bound the work.

  3. Implement across hosts

    Reuse existing components, run approved checks, and preserve a portable evidence trail.

  4. Verify and learn

    Independently test requirements, enforce the gate, measure outcomes, and promote lessons under review.

Roadmap and exit criteria

  1. M1 · Verified baseline and ECC stabilization. The Redis runbook comparison is scored. Record model, permissions, and token counters where available. Validate release lifecycle and remaining host boundaries.
  2. M2 · Context efficiency. Demonstrate fewer tokens or less reviewer effort on matched work while preserving correctness, evidence quality, and escalation.
  3. M3 · SDD governance. Extend tested spec-to-handoff coverage across representative implementation tasks and both hosts. Protect approver and verifier records.
  4. M4 · Code intelligence. Maintain a fresh dependency graph and validate cross-service impact and drift findings against real source changes.
  5. M5 · Model-flexible execution. Verify comparable approved workflows and handoff evidence across hosts and models.
  6. M6 · Enterprise assurance. Validate enforceable controls, upgrade and rollback, auditability, and organizational approval for real usage.

New SDD extensions, persistent Graphify, advanced impact and drift analysis, decision intelligence, and broader autonomy were deferred during ECC stabilization. The milestones describe the target.
